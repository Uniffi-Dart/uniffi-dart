# Unsigned 64-bit values

Rust `u64` values are returned and stored as Dart `BigInt`, covering
`0` through `18446744073709551615` exactly. Only `u64` changes: `i64`, `u8`,
`u16`, and `u32` still use `int`.

Generated inputs accept either `int` or `BigInt`. Dart has no implicit conversion
between them, so those parameters use `Object` and validate at runtime:

```dart
final BigInt small = takeU64(v: 42);
final BigInt large = takeU64(v: BigInt.parse('18446744073709551615'));
final int convenient = small.toIntChecked(); // 42
large.toIntChecked(); // RangeError, never clamps
```

`BigInt.toInt()` can clamp values outside the native `int` range. The generated
`toIntChecked()` extension checks `isValidInt` first. Native Dart `int` tops out
at `9223372036854775807`; construct larger values with `BigInt.parse` or perform
the arithmetic in `BigInt` from the start. Passing an already-overflowed `int`
cannot recover its intended value.

Negative inputs and values above u64 max throw `RangeError`. Other objects,
including strings, doubles, and booleans, throw `ArgumentError`. Parse strings
explicitly. Negative `int` values are not accepted as unsigned bit patterns.

The same rules apply inside optional values, lists, maps, record fields, enum
payloads, and aliases backed by u64. Constructors normalize immediately:

```dart
final record = U64Record(value: 42, alias: 1, values: [42, null, large]);
final BigInt value = record.value;
final List<BigInt?> values = record.values;
```

Inputs such as `List<Object?>` permit mixed int/BigInt elements. Stored and
returned collections have consistent BigInt element types. Conversion copies
the affected collections. Map inputs with distinct keys that become equal
(such as `1` and `BigInt.one`) are rejected instead of dropping an entry.

Callback method parameters use `BigInt`, since those arguments come from Rust.
Calling that callback method directly in Dart also follows its BigInt signature,
including Rust-backed implementations of `with_foreign` traits. Ordinary generated
Rust functions and methods accept int/BigInt inputs as described above.

Callback u64 results use `Object` (or
`Future<Object>`) so Dart implementations can return an ordinary `int` or a
`BigInt`. Results are validated before crossing back into Rust.

This is a source and behavior change for consumers of u64 results. Update `int`
variables, callback parameters, collection annotations, comparisons, and
arithmetic. Use `BigInt.zero`/`BigInt.from(...)` for BigInt operations, or opt
into `toIntChecked()` when the application requires a native int. `BigInt.one`
is not equal to the int `1`, including in test expectations and map lookups.
For JSON, encode BigInt explicitly, for example as a decimal string; the default
JSON encoder does not accept it.

The Rust API, eight-byte wire encoding, and Uint64 FFI signatures stay the same.
Internally, upper-half values use signed Dart int bit patterns at the native
boundary, then are lifted back to positive BigInt values.
